# @zeroflux/zfx-perps-sdk

TypeScript client for zfx-perps operator nodes. ESM, runs in browsers and Node 22 with the global
`fetch` and `WebSocket`. Dependencies: `@noble/curves`, `@noble/hashes`, `@scure/base`.

The package has two APIs:

- The spot/cross-margin node API (`ZfxPerpsClient`, `ZfxPerpsFeed`, `src/near.ts` from the root
  export). Unchanged.
- The v1 clearing API for isolated-margin perpetuals whose fills are verified on the NEAR clearing
  contract (`src/clearing`). Import it from `@zeroflux/zfx-perps-sdk/clearing`, or use the
  `clearing` namespace and `ZfxPerpsClearingClient` from the root export. The contract it
  implements is `markets/zfx-perps/openapi.yaml`.

## Clearing API

```ts
import { KeySigner } from "@zeroflux/zfx-perps-sdk";
import { ZfxPerpsClient, checkOracle, estimateMargin } from "@zeroflux/zfx-perps-sdk/clearing";

const signer = KeySigner.fromNearSecret(secret); // trading key registered with register_key
const c = new ZfxPerpsClient("http://127.0.0.1:8796", { accountId: "alice.testnet", signer });

const [market] = await c.listMarkets();
const oracle = await c.getOracle(market.marketId);
if (!checkOracle(oracle, { market }).ok) throw new Error("oracle print does not verify");

const pf = await c.getPortfolio();
const pos = pf.pending.positions.find((p) => p.market === market.marketId);
const est = estimateMargin(market, pos, "BUY", 1010n, 100n, { free: pf.pending.free });
if (est.ok) await c.placeOrder({ marketId: market.marketId, side: "BUY", price: 1010n, quantity: 100n });
```

Client methods: `getInfo`, `listMarkets`, `getBook`, `getOracle`, `getFunding`, `getPortfolio`,
`estimateMargin` (node-side), `signOrder`, `placeOrder`, `cancelOrder`, `setMinNonce`, `withdraw`,
`adjustMargin`, `deposit`, `subscribeBook`, `subscribeOrders`.

- Prices are integer ticks, quantities lots, money collateral atoms. All of them, plus nonces and
  timestamps, are `bigint` in TypeScript and decimal strings on the wire. Parsers reject JSON
  numbers that are not safe integers.
- `signOrder` fills the chain id and clearing contract from `/v1/info` (cached), the policy hash
  from the market, a nonce from `nextNonce()` (starts at `Date.now() * 1000`, strictly increasing
  within the process), expiry now + 1 h, a unique client order id, and `maxFeeBps` (maker fee for
  post-only, otherwise the larger of maker and taker). It checks the order against the market's
  limits before signing.
- `setMinNonce()` with no argument uses a fresh nonce as the floor. Every order signed before the
  call becomes unfillable here and on-chain; orders signed after it stay valid.
- `withdraw` and `adjustMargin` use `nextNonce()` as the action nonce unless you pass one.
- `deposit` returns the `ft_transfer_call` wallet transaction for the collateral token and sends it
  if you pass `send` (for example `wallet.signAndSendTransaction`).
- `subscribeBook` keeps a bigint L2 book from snapshot plus deltas and re-subscribes on a sequence
  gap or a lagged notice. `subscribeOrders` signs the WebSocket auth message and delivers account
  events. Both reconnect after an unexpected close.

Standalone pieces:

- `wire.ts`: canonical signed messages (`orderMessage`, `cancelMessage`, `minNonceMessage`,
  `withdrawMessage`, `marginMessage`, `authMessage`) and `orderHash`. Identifiers are validated
  like `wire.rs`, so a `|` or an upper-case hash throws.
- `print.ts`: OraclePrint v1 `encodePrint`/`decodePrint` (strict), `printHash`, `verifyPrint`
  (distinct allowlisted reporters with valid signatures, at least `quorum`) and `checkOracle`,
  which also checks the claimed hash and fields, freshness and the implied mark. Pass the reporter
  list from `ClearingReader.state()` to avoid trusting the node's copy.
- `margin.ts`: bigint port of the ledger's `initial_margin`, `maintenance_margin`, `fee`, `equity`
  and `liquidation_price`, and `estimateMargin`, which follows the ledger's margin rule and returns
  the initial margin, fee, loss against the mark and the free collateral the fill needs.
- `near.ts`: `clearingTx.*` wallet transactions for every user call on the clearing contract
  (`register_key`, `remove_key`, `cancel_order`, `set_min_nonce`, `request_forced_withdrawal`,
  `freeze`, `escape_scan`, `escape_withdraw`, `reclaim_deposit`, deposits) and `ClearingReader`
  for the views.

## Tests

```sh
pnpm install
pnpm typecheck   # src, examples and tests
pnpm test
```

`test/clearing.test.ts` checks every entry of `test/clearing_vectors.json` (generated by the Rust
crate `zfx-perps-clearing`, test `vectors`) byte for byte, plus margin math with hand-computed
numbers and the client against an in-memory fake node. `test/node.test.ts` runs the spot API
against the Rust node binary and needs it built.

Examples: see `examples/README.md`.
