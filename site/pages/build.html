Build · ZFX VPN

A private AI endpoint for the models you already use.

ZFX VPN sits between your code and the model. It finds sensitive values in every request, swaps them for placeholders the model never sees, and puts the real values back in the answer. What can't be made safe goes to a verified confidential NEAR AI model, or nowhere.

Two ways to use it

Protect your users. Protect yourself.

For builders

Protect your app's users

Point your product's OpenAI-compatible client at ZFX VPN. Your end users' emails, phone numbers, health details and IDs never reach the model provider, and replies come back with the values restored for the right user only. Works with Chat Completions and Responses, streaming or not, including tool calls.

Demo: vpn/demos/builder-app
For developers

Protect your own workflow

Point your coding agent at http://127.0.0.1:8787/v1. Keys and passwords in files the agent reads are blocked on your machine; your name, customers and project codenames become placeholders. Detection rules, your registered terms and the audit log never leave the device.

How a request is handled

Checked before it leaves.

Every message, system prompt, tool definition and tool result is scanned by rule-based recognizers with checksums, your exact registered values, and an on-device span model (GLiNER). A deterministic policy decides each finding: allow, placeholder, redact, hold for review, route privately, or block. The route is fixed before the first byte streams back, and a failed check never falls back to a less private route.

Privacy tierMeansMay receive untransformed content
LOCAL_ONLYRuns on this device, for example a loopback Ollama modelOnly if you allow local private handling
TRANSFORMED_PUBLICAny public or unverified modelNever. Transformed content only
ATTESTED_CONFIDENTIALA NEAR AI model whose provider-level TEE attestation verified for that exact model, minutes agoOnly with your consent, never critical categories
UNVERIFIED_EXTERNALClaims confidentiality but did not verifyNever. Treated like a public model

A verified TEE is still remote and still runs software that can have bugs. A gateway signature, or a model merely listed on NEAR AI, does not count as verified.

Three ways to run it

Choose who sees the raw prompt.

ModeWho sees the raw promptUse for
Local daemon zfx-vpnOnly your machineAnything sensitive. The strongest control
Hosted gateway zfx-vpn-hostedThe hosted service and its operators, before transformationConvenience when you trust the operator. Not zero-knowledge, not an enclave

ZeroFlux does not run a public hosted gateway yet. The gateway is open source: run it yourself with zfx-vpn-hosted.

Install

Two minutes to a private endpoint.

The installer builds from source with Rust, puts zfx-vpn in ~/.local/bin and never uses sudo. macOS is the primary platform. Prompt VPN installs are migrated in place, and the promptvpn command keeps working.

macOS · Linux builds but has not been tested yet
curl -fsSL https://raw.githubusercontent.com/zerofluxprotocol/zeroflux/main/vpn/install.sh | sh
zfx-vpn init            # guided setup
zfx-vpn connect test    # proves protection with synthetic data against a local mock

# point any OpenAI-compatible client at it
export OPENAI_BASE_URL=http://127.0.0.1:8787/v1
export OPENAI_API_KEY="$(cat "<data dir>/apps/default.key")"   # path shown by: zfx-vpn connect show

# or let it configure a coding agent, with a backup
zfx-vpn client configure codex      # also aider, opencode
What it does not do

ZFX VPN inspects requests sent to its API. It does not see what an agent does outside that API, such as running curl or driving a browser, and it does not filter network traffic. Detection is not perfect: the measured misses are published in the evaluation report. Images, audio and files can't be inspected and are blocked for remote models by default.
