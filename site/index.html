The technology

Proof of work, reimagined for the AI era.

BEFORECryptographic hashing
ZEROFLUXMatrix computation on AI accelerators

Each mining attempt runs a 64 → 4096 → 4096 → 4096 → 4096 → 256 network of integer matrix layers, about 51.6 million multiply-adds, then hashes the output. Miners batch thousands of attempts into ordinary GEMMs on int8 or FP8 tensor cores. Every value is a small integer, so int8, FP8, Metal and CPU arithmetic all produce the identical result, bit for bit.

Matrix-native

Computational work centered on matrix operations, rather than conventional hash-only mining.

Hardware-accelerated

Runs on NVIDIA and AMD tensor cores through cuBLAS and hipBLASLt, and on Apple Silicon GPUs through MLX and Metal.

Independently verifiable

A node checks a block by recomputing one attempt on a single CPU core. No GPU is needed to run a full node.

The network

Compute secures the network.

ZeroFlux is an independent proof-of-work blockchain with its own native asset, ZFX. Miners contribute computational power, compete to produce blocks, and receive protocol rewards when they successfully mine valid blocks.

01
Open participation

Anyone with compatible hardware can participate in mining.

02
Compute-native consensus

Proof of work designed around matrix computation and AI accelerators.

03
Steady block times

Difficulty adjusts every block. In simulation, a miner with 30% of the hashrate faking timestamps still gets 61-second blocks on a 60-second target.

04
Bridged to NEAR

Lock ZFX on ZeroFlux and receive wZFX, a standard NEAR token that trades through NEAR Intents. Live on NEAR testnet at wzfx.zeroflux.testnet. Version 1 is secured by a 2-of-3 committee.

Get Started
Run it yourself

From source to mined blocks in minutes.

Everything runs locally: three nodes, miners, a wallet, the block explorer, and the full NEAR bridge against a local NEAR sandbox. One command checks every claim on this page and writes an evidence report.

macOS or Linux · Rust 1.90+, Python 3.11+ with uv, a C++17 compiler
# build, then check bit-exactness against the published test vectors
cargo build --release && make -C miner/cuda cpu
./target/release/zpu-cli selftest

# start a node and mine on it (explorer at http://127.0.0.1:9441/)
./target/release/zfx-wallet new
./target/release/zfx-node --devnet --data-dir /tmp/zfx --explorer-dir explorer/dist &
./target/release/zpu-cli mine --node http://127.0.0.1:9441 --address zfx1...

# mine on an Apple Silicon GPU instead
./target/release/zpu-cli mine --node http://127.0.0.1:9441 --address zfx1... \
  --backend exec --exec ".venv/bin/python miner/python/zpu_miner.py --backend mlx"
Full verification · about 25 minutes on a laptop
make check          # lint, unit tests, test vectors in Rust, C++, Python, MLX
make e2e-native     # 3 nodes, 1,000+ blocks, restarts, reorgs, encrypted P2P
make e2e-bridge     # 100 ZFX ⇄ wZFX round trips with injected faults
make e2e-intents    # swaps through the official NEAR Intents contract
make acceptance     # all of the above, then ACCEPTANCE_REPORT.md
