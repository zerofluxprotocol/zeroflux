The technology

Proof of work, reimagined for the AI era.

BEFORECryptographic hashing
ZEROFLUXMatrix computation on AI accelerators

Each mining attempt runs a 64 → 4096 → 4096 → 4096 → 4096 → 256 network of integer matrix layers, about 51.6 million multiply-adds, then hashes the output. Miners batch thousands of attempts into ordinary GEMMs on int8 or FP8 tensor cores. Every value is a small integer, so int8, FP8, Metal and CPU arithmetic all produce the identical result, bit for bit.

Matrix-native

Computational work centered on matrix operations, rather than conventional hash-only mining.

Hardware-accelerated

Runs on NVIDIA and AMD tensor cores through cuBLAS and hipBLASLt, and on Apple Silicon GPUs through MLX and Metal.

Independently verifiable

Anyone can recheck a block on a CPU in milliseconds. To prove a bad block wrong, you name one value and NEAR recomputes just that value.

On NEAR

NEAR keeps the ledger.

ZeroFlux settles on NEAR: ZFX is a standard NEAR token, minted only for proof of work. Miners submit winning attempts to a NEAR contract with a bond. A block counts unless someone proves it wrong during a challenge window; then the reward is minted. No separate chain, no bridge.

How ZFX settles on NEAR
01
Open participation

Anyone with compatible hardware can mine. Difficulty retargets on-chain every block.

02
Cheap to submit, cheap to dispute

Posting a block costs about 6 Tgas of NEAR gas. Proving a bad block wrong costs about 4.5 Tgas: NEAR regenerates one row of weights and recomputes one value.

03
Fraud doesn't pay

A cheater's bond goes to whoever catches them, and every block built on a bad one is reverted. The watcher ships with the mining tools.

04
Native to NEAR

ZFX works with NEAR wallets and trades through NEAR Intents directly, with nothing to bridge.

Get Started
Run it yourself

From source to mined blocks in minutes.

Everything runs locally: a NEAR sandbox, the ZFX contract, a watcher and your miner. One command checks every claim on this page and writes an evidence report.

macOS or Linux · Rust 1.90+, Python 3.11+ with uv, a C++17 compiler
git clone https://github.com/zerofluxprotocol/zeroflux && cd zeroflux

# build, then check bit-exactness against the published test vectors
cargo build --release && make -C miner/cuda cpu
./target/release/zpu-cli selftest

# local NEAR sandbox + ZFX contract + watcher + mining proxy
make localnet &
./target/release/zpu-cli mine --node http://127.0.0.1:9561

# mine on an Apple Silicon GPU instead
./target/release/zpu-cli mine --node http://127.0.0.1:9561 \
  --backend exec --exec ".venv/bin/python miner/python/zpu_miner.py --backend mlx"
Full verification · about 25 minutes on a laptop
make check          # lint, unit tests, test vectors in Rust, C++, Python, MLX
make e2e-near       # mining on NEAR, cheaters caught at every layer, ZFX on NEAR Intents
make security-test  # fuzzing, sanitizers, audit, reproducible build
make acceptance     # all of the above, then ACCEPTANCE_REPORT.md
